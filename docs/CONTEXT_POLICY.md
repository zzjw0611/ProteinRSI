# 按需读取证据与研究笔记

自然语言 `start` 创建的新研究启用 `research.context_policy=evidence-v1`。
A/B/C/M/E 通过同一控制端上下文入口调用模型，原生 API 和 Assistant Bridge 均支持。
这改变的是证据的传递方式，不改变任务类型、实验指标、设计自由度或验收权限。
旧研究缺少此配置时仍使用原路径；不能给已冻结的运行直接改配置来迁移。

## 一次决策的流程

1. 控制端冻结该决策原本有权看到的完整输入，按内容生成引用。
2. `ContextBuilder` 保留小字段，将大表、历史、代码、结构文本和大规格表替换成描述符。
   描述符包含来源路径、类型、条数和字节数；这些不是被抽样出来的科学结论。
   小型任务约束、预算和当前步骤仍直接可见，完整原件始终可读。
3. 模型可以直接作答，也可以返回 `_context_action` 请求证据页。
   每页最多 50 条、约 12KB；大行中的字段继续使用子引用，逐页可无损恢复。
   字符串游标按字符而非字节推进。对象按键分页。
4. 下一次模型请求携带最新页和读取记录。先前页不会不断附加进对话；全部页保留在审计中。
   每次决策最多 12 个读／记笔记动作，最后一个模型回合必须返回原有决策格式。
   错误引用返回可修复错误，并占用动作次数；超限暂停，不偷偷增加重试。
5. 模型可写带证据引用的研究笔记：假设、反证、失败、未决问题和下一步。
   C-feedback、A-review、M 的实际返回也保存为版本化决策笔记。
   笔记是模型主张，不是实验结果，也不是未返回的内部思维过程。
6. 原有模块校验最终结果，工具执行、实验提交、预算和方法验收继续经过原控制器。

示例读取（ref 只能来自这次决策已发放的描述符）：

```json
{"_context_action":{"kind":"read","ref":"ev-…","offset":0,"limit":20}}
```

模型如需分析全部观测，应调用 `research_python`，直接读取
`context['observations']`、`context['history']` 等完整已揭示数据，不应把数据表抄进代码。
新策略将这份数据通过独立沙箱输入文件传递，避免 4MB 命令管道上限；
输入数据仍有 64MB 本地资源保护，输出仍有原有大小和执行时间限制。
沙箱无法读取实验标签库、控制器数据库、API 密钥或网络。

## 范围、预算与恢复

- 引用只授权本次决策已经有权看到的输入；不接受数据库 namespace、任意文件路径或其他决策的引用。
- 所有未揭示测量，包括 M/E 验证用到的新测量，仍走原实验预算。
  本地分页不收实验名额；每次实际模型请求照常收取 LLM 调用预算。
- 最近最多三条研究笔记进入上下文目录。仅复用同一任务、轮次不晚于当前且观测为当前证据子集的笔记。
  E 不自动导入这些建议，避免给验收额外注入意见。跨研究的自动长期记忆不在此实现中。
- 会话第一次创建时冻结笔记选择。暂停／重启会复用原帧和已完成模型请求；不会引入后续轮次的新笔记。
  结果未知的网络请求仍需原有恢复流程，不自动重发。
- 模型上下文帧上限 48,000 UTF-8 JSON 字节，其中给分页、笔记和读取记录留有空间。
  完整 HTTP 请求（含提示、Schema、API 包装）仍受原生精确字节预检约束。
  输出 token 额度沿用 provider 配置。字节上限不是模型 tokenizer/context-window 认证；
  特别大的静态提示或输出 Schema 仍可能触发预检，应检查对应来源。

## 轨迹与实现

`proteinrsi trace --campaign <run> --format html` 可查看新增事件及原件侧文件：

| 记录 | 用途 |
| --- | --- |
| `context_sessions` | 固定输入引用、笔记快照、待完成／完成状态 |
| `context_evidence` | 原始值及来源路径，控制端专属 |
| `context_frames` | 每次送给模型的实际上下文和大小 |
| `context_reads` | 模型提出的读取／笔记动作、对应响应或错误 |
| `research_notes` | 有出处的版本化模型笔记／决策 |

终端的 `context_prepared` 同时显示原输入和实际上下文字节数。
验证子运行的记录使用 `validation_` 前缀归入主运行轨迹，费用归入主预算。
这些新 namespace 不对研究 worker 的通用数据库 RPC 开放。

主要代码：`research/context.py`（构建、读取、笔记和恢复），`llm.py`／`assistant_bridge.py`
（统一入口及既有 provider 预检），`research/code.py`／`code_worker.py`（沙箱数据输入）。

## 验证范围

新增测试覆盖 5／20／100 轮合成历史的请求大小、原始证据完整性、分页重建、
跨决策访问拒绝、笔记的轮次和证据隔离、暂停恢复不重复付费、验证分支计费与轨迹、
以及超过 4MB 的沙箱已揭示数据输入和隐藏文件访问拒绝。
这些是离线机制测试，不代表已经运行 100 轮真实 LLM 实验或验证科研收益。

2026-10-08 离线核对：全套回归 914 项通过、5 项因可选依赖缺失跳过；
收尾的上下文边界测试 11 项通过，Bridge／通用研究集成组合 76 项通过。
Ruff 和 wheel 构建通过。对已有 GB1 第四轮被拦截请求进行本地 MockTransport 重放，
首次 HTTP 请求由 290,548 字节降至约 31KB；原运行数据库只读，未联网、未推进实验。
这仅比较首次请求大小，后续按需读取仍会消耗模型调用和 token。
