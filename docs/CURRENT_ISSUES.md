## 当前实现与已经完成的修复

- 自然语言目标启动，任务约束由 TaskSpec 表达；支持开放序列设计、实验回放及计算任务。
- 蛋白设计工具可选，由 Agent 决定是否调用；支持隔离执行的 `research_python`。
- 开放设计不提供回放候选目录，隐藏 fitness 仅由控制器按查询揭示。
- 提供的母本实测值作为免费初始证据；无记录查询返回 unavailable 并占预算，不插补 fitness。
- 临时网络错误和 HTTP 502 等支持有限重试、独立计费和审计。
- `full_plate` 模式要求提交整板，不足则在同一轮补齐；补齐上限 6 次，耗尽后停止，不预占实验预算。
- 候选排序采用稳定 ID，并有有限格式修复；开放任务不向 Agent 展示旧的 128 条候选池参数。
- W/M 验证根据候选数量安排等量、互不重复的组，剩余孔位用于研究，研究孔不进入方法比较统计。
- 保存模型实际返回的说明、工具结果、方法验证及预算轨迹，不推测未返回的内部思考。

## 原快照最新失败的根因（已由数据交接修复覆盖）

日志错误：`RuntimeError: Guarded worker failed: ValueError: Each edit needs position, from, to`。

第二轮 Python 工具执行成功。B 随后再次表示候选时，返回了自创格式：

```json
{"label": "E001", "position/from/to": "40/D/W,41/G/A,54/V/A"}
```

执行代码实际要求：

```json
[
  {"position": 40, "from": "D", "to": "W"},
  {"position": 41, "from": "G", "to": "A"},
  {"position": 54, "from": "V", "to": "A"}
]
```

`src/proteinrsi/agents.py` 的设计输出仍使用任意字典表示 edits，schema 没有准确表达必填字段；`src/proteinrsi/tasks.py` 的 apply_mutations 到执行时才拦截。设计格式错误没有像排序一样接入有界修复。LLM 对已经由 Python 生成的数据再次抄写，增加错误和上下文开销。

此前修复针对排序与整板容量，没有覆盖这一设计数据交接缺口，不能将系统称为已完全解决输出格式问题。

## 用户确认的架构方向（分阶段实施）

用户给目标和初始输入，由 LLM 先定义能闭环循环的研究协议，包括每一步的输入输出、执行方式、反馈、失败处理与停止条件。A/B/C/M 可以作为角色能力，不能限制所有任务只能执行固定操作流程。

建议分层：

1. 目标与输入约定：记录用户目标、指标、资源和硬限制，缺失必要信息时询问。
2. 协议设计：LLM 定义步骤、数据 schema、连接、条件分支及有界循环；已有工具接口从注册信息读取。
3. 协议预检：检查上下游兼容性、资源、权限、预算和停止路径；错误交给 LLM 修订。可执行不代表科学策略有效。
4. 通用执行：结果保存为有类型的资源，通过 ID 引用，支持局部修复和断点恢复。
5. 独立实验控制：整板要求、标签隔离、计费与用户限制不可由 Agent 自行改写。
6. M 协议改进：允许提出步骤、代码、连接或接口补丁；兼容性检查与效果验证分开，新增实验仍计费。

不同任务可有不同 schema，不能强制 binder、排序与突变任务全部返回突变列表。自定义 schema 不能赋予实测来源、预算或权限。
