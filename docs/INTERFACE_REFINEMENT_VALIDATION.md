# 接口职责整理与真实验证（2026-10-11）

修改保留现有工作流执行器，没有新建一套 Agent 框架。研究目标、科研步骤、候选和可选工具由 LLM 决定；系统管理契约、身份、权限、预算与方法采用。

## 职责与改动

| 边界 | 负责内容 |
| --- | --- |
| A / 协议执行器 | 科研问题只写 Step.question；登记的适配器接收问题。Binding 可只给 source，执行器推导上游类型；显式类型仍校验。 |
| A-plan / A-review 修复 | 保存原始草稿、失败原因和每次编辑；局部 JSON 编辑后重新校验完整协议，不能改写已完成步骤。 |
| 上下文 | 操作列表、Schema 字典都按精确名称读取；成功读取保留到显式 release。容量不足拒绝新读，不静默丢证据。完整规格仍可追溯。 |
| 提供方适配器 | 保留 Responses 消息与 phase，解析唯一最终回答，说明消息单独保留。拒绝猜测散文中的 JSON、多个答案或不完整消息。 |
| B / 工具网关 | 告知局部剩余工具轮次；最终阶段只提交候选或请求重规划。代码失败返回反馈，工具回执持久化，不当作实验数据。 |
| M / 治理控制器 | 告知冻结修改策略；前置校验和控制器共用规则，超限提案有界修复。控制器仍独占暂存、验收、采用和回退权限。 |

局部步长守卫不等于全局 LLM/工具调用预算。此次研究的总调用数不设上限；实验查询严格限制为 48。
