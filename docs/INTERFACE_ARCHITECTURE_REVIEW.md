## 结论

已有 TaskProfile、OperationRegistry、ResourceStore、实验控制器和方法治理可以继续作为基础。
主要缺口是：同一类结果通过不同入口时，会经历不同的构造、校验、修复和持久化流程。
应在现有执行器中统一结果处理，区分模型可撰写的数据与系统登记后的资源；保持科研步骤和任务数据格式可扩展。

## 可复现的直接缺陷

本次 B 的第一条候选为 V39I，返回 ID 为 `seq:` 加63个0和1。
定点调用结果：

```text
standard_registry().validate(SEQUENCES, value, output=True) → 通过
SequenceSet.model_validate(value) → ValidationError
isinstance(error, ContractError) → False
```

JSON Schema 只能验证该 ID 的字符形状；序列哈希匹配属于资源语义校验。
现有执行器因此未进入 ContractError 修复路径。这是接口缺陷的复现，不是实验效果评估。

上下文日志也显示：A-plan 12次读取请求中，operations 的 offset=0 读了5次，offset=9 读了3次，resources 读了2次，之后才输出计划。
这支持“目录与工作集需要改善”的判断；不说明每次读取都没有科研价值。

## 收敛为四类契约

### 1. TaskContract：任务要求

记录目标、用户输入、允许操作范围、反馈来源、指标/单位、预算及终态输出。
LLM 根据目标提出任务解释和科研协议；控制端确认数据集事实及权限后冻结。
不同任务的输出可以不同：变体集合、排序、结构或预测表。

### 2. OperationContract：一个步骤怎样执行

在已有 Operation/ToolSpec 基础上明确：

- 描述、适用条件、权限和代价信息。
- 输入 Schema。
- 模型草稿 Schema 或原生工具返回 Schema。
- 系统适配函数：补充 ID、登记文件、关联来源，不擅改科研内容。
- 最终资源 Schema 与任务/来源验证器。

内置操作、自定义 Agent、Python、蛋白工具共享这一执行边界。
自定义中间分析仍可使用 custom.* Schema；转为候选、结构、指标等标准资源时必须经过注册适配器。
纯分析表可以直接保存为非权威计算资源，不能自授实测或验收权限。

### 3. Resource：已经登记的数据

系统生成资源 ID、内容哈希、Schema 版本、作用域、生产者和来源引用。
LLM 可以选择已发放的引用，不负责计算新资源身份、伪造文件路径或声明实测来源。
原始数据、执行成功、格式合法和科学有效性分别记录；计算结果不自动成为实验反馈。

### 4. ExecutionReceipt：发生了什么

记录步骤、尝试、原始输入/返回引用、执行状态、校验状态、有效输出引用、问题和实际成本。
至少区分：输入不合法、已知执行失败、执行结果待校验、校验失败、有效完成、执行结果未知。
执行器根据类型决定修复参数、修复草稿、重做适配、重新规划或等待核对。
不将权限拒绝、预算耗尽或未知执行状态当成普通格式问题循环重试。

## 统一执行过程

```text
检查输入与权限
→ 执行或读取原执行回执
→ 保存原始返回
→ 适配并生成系统字段
→ 校验结构、任务约束和来源
→ 原子登记合法资源与完成状态
→ 向后续步骤交付引用
```

原始工具返回已保存时，适配错误只重做适配与校验。
需要模型改变科学内容时才请求草稿修正，所有真实调用继续记账。
有效的验收否决、M不修改、工具返回科学上的阴性结果，都不能被“自动修复”成期望结果。

## 不同任务的示例

- GB1：模型提出 `edits=[[{"position":39,"from":"V","to":"I"}]]`；适配器还原序列、计算 ID，领域验证器检查母本和位点。去重及面板数量由面板验证器检查。
- 排序：模型对已提供候选引用给出次序和理由；验证器检查没有偷偷添加或遗漏候选。
- Binder：模型定义设计/预测/筛选步骤，工具产生序列和结构文件；系统登记文件并保留靶标、链与残基对应关系。
- 自定义指标：模型提出计算定义、代码和输出 Schema；沙箱执行，适配器登记指标值、单位、对象及来源。实验值仍只来自实验控制器。
- M：模型提交 W/M 补丁草稿；系统绑定基版本和内容版本；E 根据冻结证据验收，治理模块负责采用或回退。

## 实施顺序和验收

1. **先修正确性**：统一草稿→资源入口，覆盖自定义 Agent；禁止模型直接生产系统身份字段；将结构/语义/来源错误统一路由。
2. **再修恢复性**：持久化原始执行回执；复用 E 的冻结输入修复原则；校验失败不重复运行已经完成的工具。
3. **再改可用性**：短工具目录、按名查规格、受限工作集；清晰展示 ready 阶段下的 blocked 执行状态。
4. **再验证扩展性**：用设计、排序、结构和自定义指标契约测试验证，不把框架写成 GB1 专用流水线。

必须通过的行为测试：同一序列从内置/自定义/Python入口产生相同身份；LLM不需要计算哈希；非法位点可定位修正且不扣实验预算；工具成功而适配失败时不重复工具执行；跨作用域引用被拒绝；格式修复不改变 E 的科学证据；M无修改可正常结束；100轮证据增长下选中规格可复用且请求保持有界；重启后的步骤和费用不重复。

旧运行保留原快照与失败证据。接口新版本应在新研究中验证，避免改代码后把旧失败记录直接当成新实现的运行结果。
