# 协议启动与执行修复（2026-10-06）

基于远程 feat/typed-dataflow-protocols 的 0229a22，在完整项目中接通自然语言启动并修复部署问题。没有恢复或重新创建正式 GB1 实验。

## 新建研究的执行路径

1. 用户给目标、初始输入及预算；goal-intake 整理任务约定，缺失必要信息时澄清。
2. 新建 start 默认保存 typed 模式；LLM 获得任务、已揭示证据、工具真实接口和输出契约。
3. LLM 生成本轮步骤、输入绑定、输出 schema 和依赖。自定义中间格式使用 custom.* 命名空间。预检通过才执行。
4. 工具和代码结果形成不可变资源，后续步骤通过资源 ID 读取；原生候选集不需 LLM 再次抄写。
5. schema 或数据连接错误交回 LLM 有界修复。执行错误只允许修订未完成部分，成功工具收据复用；次数跨恢复累计。完成状态不明的操作仍停止等待核查。
6. 最终结果经过任务边界校验。实验路径由原控制器执行整板、去重、权限、预算与反馈；计算路径保存计算结果而不制造实测观测。
7. 新反馈和上一轮协议结果进入下一轮上下文，LLM 重新规划；达到用户轮次或预算限制后生成报告。

例如，新建 GB1 研究可以使用自然语言 start 并加 --full-plate；--protocol-mode legacy 是显式兼容选项。--prepare-only 不调用研究规划或实验，仅保存任务。旧研究及旧澄清记录保留原模式，不进行无提示的协议迁移。

## 修复内容

- 给 tests/dataflow 增加包边界，解决 conftest 模块名冲突，标准 pytest 命令可直接运行。
- 将 jsonschema.SchemaError 转成包含字段位置的 ContractError，进入原有有限规划修复。
- 增加执行期输入/输出映射错误的有限修复；保存错误、协议版本及成功操作收据。
- 将当前补板/验证请求上下文纳入资源与执行作用域，避免同一轮第二次补板复用第一次候选。
- 自然语言新任务默认 typed，澄清时保留模式，启动摘要明确显示模式。
- 新协议计划、修复及阻塞进入现有轨迹；不增加 worker 的实验或数据库权限。
- Ruff 排除冻结实验归档，其中生成程序依赖沙箱注入的 context/inputs 等变量，不是项目运行源码。

## 验证与限制

使用人工标签、MockTransport 和真实目标机隔离机制验证：两轮整板（每板384）、同轮多面板补齐、重复恢复不重复计费、无效 schema 修复、成功工具只执行一次、修复次数跨恢复累计，以及自然语言排序任务的两轮计算反馈（无强制设计或蛋白模型调用）。全部测试及构建结果见 DATAFLOW_VALIDATION.md。

当前协议定义每轮的有序依赖图及有限后缀修订；跨轮反馈与停止上限由可信控制器负责。尚无任意嵌套循环或完整的声明式条件语言。M 沿用现有 W/M 方法建议与实验验收，可影响后续协议规划；任意协议拓扑、schema、代码的持久 M 自修改验收仍是下一阶段。没有使用付费真实模型、新 GPU 推理或实测景观重新开展研究；机制测试通过不代表科研效果已经提升。
